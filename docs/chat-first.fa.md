# گفتگو، مهارت و پیوست — ۰٫۲٫۳

این تغییر، فلوی اصلی محصول را به گفتگو برمی‌گرداند:

- سؤال عمومی یا سلام: پاسخ مستقیم، بدون خواندن اجباری پروژه یا ساخت برنامه.
- سؤال وابسته به پروژه: فقط فایل‌های لازم خوانده می‌شوند.
- درخواست تغییر کد: برنامه در خود گفتگو نمایش داده می‌شود؛ ویرایش/تأیید/اصلاح همان‌جا انجام می‌شود.
- پایان پاسخ، پایان گفتگو نیست؛ پیام بعدی روی همان thread ادامه پیدا می‌کند.
- درخواست تازه، تأیید اجرای قبلی را لغو می‌کند؛ تغییر کد تازه بدون تأیید تازه اجرا نمی‌شود.
- ستون inspector حذف شد. فعالیت و کیفیت اختیاری‌اند؛ بازبینی تغییرها نیز داخل همان صفحه باز می‌شود.
- متن‌ها و دستور پاسخ کوتاه‌تر شدند؛ مراحل فنی بی‌دلیل به کاربر گفته نمی‌شوند.

## Skill

کنار composer دکمهٔ «مهارت» وجود دارد. انتخاب یک مهارت، /نام‌مهارت را داخل پیام
می‌گذارد و خودکار ارسال نمی‌کند. فراخوانی صریح به مدل می‌گوید همان SKILL.md را بخواند.
این مسیر از مهارت‌های فعال و pin‌شدهٔ واقعی استفاده می‌کند، نه یک برچسب تزئینی.

افزودن ساده: نام، کاربرد، متن دستور → یک تأیید اعتماد → ذخیره و فعال‌سازی.
همین کار بدون ساخت دستی پوشه، YAML یا نوشتن مسیر ممکن است. انتخاب پوشهٔ Skill
هم هست و فایل‌های همراهش حفظ می‌شوند؛ متن پیش از فعال‌شدن برای بازبینی نشان داده می‌شود.
تنظیمات hash/source/pin زیر جزئیات پیشرفته رفته‌اند. نسخه‌های تسک جاری بدون تصمیم
کاربر عوض نمی‌شوند؛ برای مهارت تازه در یک تسک موجود، به‌روزرسانی مهارت‌های همان تسک لازم است.

## فایل‌ها

مقصد «فایل‌ها» به «پیوست‌ها» تغییر کرده است. فهرست منابع و فایل‌های از قبل موجود مخزن
در آن نمایش داده نمی‌شود. فایل واقعی کاربر حذف نشده است.
پیوست در composer بارگذاری می‌شود و فقط همان فایل ارائه‌شده در .bridge-attachments
پروژه ذخیره می‌شود؛ سقف فعلی هر فایل ۲ مگابایت است. انتخاب ارجاع به فایل پروژه همچنان
از کنترل جداگانهٔ «فایل پروژه» ممکن است و خودکار همهٔ فایل‌ها را وارد context نمی‌کند.

## شواهد

تست دسکتاپ با API و Deep Agents واقعی و provider کنترل‌شدهٔ محلی، پاسخ بدون ابزار به
سلام، ادامهٔ همان گفتگو، ساخت و فراخوانی Skill با read_file واقعی، نمایش برنامه داخل
گفتگو و جدابودن پیوست‌های کاربر از فایل‌های مخزن را بررسی می‌کند.
کیفیت انتخاب ابزار توسط provider واقعی، رفتار احتمالی مدل است؛ این تست ادعای ارزیابی
کیفیت همهٔ مدل‌ها ندارد. سیاست، مجوزها، دو repair، snapshot و پذیرش واقعی Docker حفظ‌اند.

شواهد این نسخه در checks/chat-first است؛ نتایج نهایی پس از تست نسخهٔ نصب‌شده ثبت می‌شوند.


نتیجهٔ هسته روی این تغییر: ۴۲۲ passed، ۳ skipped؛ تست‌های واقعی Docker و toolchain در همین اجرا پاس شدند. قرارداد فرانت‌اند: ۴۴ passed؛ TypeScript و build پاس شدند.

نسخهٔ ۰٫۲٫۳ نصب شد؛ ۱۰ بررسی روی نسخهٔ نصب‌شده در دو اندازهٔ پنجره پاس شد. آرتیفکت‌ها، hashها و نتیجهٔ نصب در checks/chat-first هستند.
