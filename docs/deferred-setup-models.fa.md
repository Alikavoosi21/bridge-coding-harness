# راه‌اندازی اختیاری و اتصال مدل — ۰٫۲٫۲

«رد کردن» معرفی یا «بعداً تنظیم می‌کنم» در هر گام setup، کاربر را وارد خود برنامه
می‌کند. این تصمیم در تنظیمات ذخیره و بعد از بازکردن دوباره حفظ می‌شود؛ setup کامل
اعلام نمی‌شود و هیچ disclosure، grant یا اجازهٔ اجرا به‌جای کاربر تأیید نمی‌شود.
خانه و تنظیمات بدون پروژه قابل دسترسی‌اند. شروع تسک تا انتخاب پروژه غیرفعال است.
«ادامهٔ راه‌اندازی»، «اتصال مدل» و انتخاب پروژه در دسترس می‌مانند.

اتصال مدل داخل برنامه است: preset سرویس یا Base URL سفارشی → ورود API key →
دریافت فهرست مدل‌ها → جستجو و انتخاب → ذخیره و پیش‌فرض. نام دستی مدل برای سرویس‌هایی
که endpoint فهرست ندارند باقی می‌ماند. فهرست، اثبات tool calling یا مجوز استفادهٔ
قطعی از همهٔ مدل‌ها نیست؛ probe مستقل این توانایی را بررسی می‌کند.

فهرست از /models همان سرویس با Authorization header دریافت می‌شود؛ برای endpoint
رسمی Anthropic از /v1/models و x-api-key استفاده می‌شود. کلید در URL، فایل تنظیمات
یا پاسخ API عمومی نیست. کلید ذخیره‌شده به endpoint عوض‌شده ارسال نمی‌شود؛ redirect
دنبال نمی‌شود. خطاهای authentication، unsupported catalog و شبکه جدا هستند.
هیچ محتوای پروژه برای دریافت catalog فرستاده نمی‌شود و discovery چیزی ذخیره نمی‌کند.

## منابع الهام و مرز اقتباس

الگوی «connect provider → choose model» از مستندات رسمی OpenCode بررسی شده است:
https://opencode.ai/docs/providers/
https://opencode.ai/docs/models/

تلاش خواندن فایل dialog-connect-provider در GitHub به 404 رسید؛ بنابراین ادعای
اقتـباس سورس یا سازگاری همهٔ providerهای OpenCode نداریم. پیاده‌سازی این محصول مستقل
است و فقط همان endpointهای سازگار OpenAI و Anthropic موجود در برنامه را گسترش می‌دهد.
قرارداد endpoint فهرست مدل از مرجع رسمی OpenAI نیز بررسی شد:
https://developers.openai.com/api/reference/resources/models/methods/list

شواهد backend و UI در checks/deferred-models ثبت می‌شوند. تست UI از provider محلی
با کلید آزمایشی استفاده می‌کند؛ این تست جایگزین پذیرش provider واقعی کاربر نیست.


یک ایراد مربوط به مدلِ دارای probe ذخیره‌شده نیز رفع شد: metadata قابلیت‌ها دیگر
به سازندهٔ ModelSpec داده نمی‌شود؛ مدل پیش‌فرضِ انتخاب‌شده واقعاً به runner می‌رسد.
همچنین فعال‌شدن دکمه‌های معرفی تا اتمام snapshot اولیهٔ تنظیمات صبر می‌کند تا
پاسخ دیررس شروع برنامه، تصمیم deferred را بازنویسی نکند.

بررسی‌های مرتبط: ۴۱ تست backend، ۴۴ قرارداد، TypeScript و build پاس شدند.
۱۵ بررسی UI و API شامل فراخوانی مدل انتخاب‌شده توسط Deep Agents/LangGraph با
کلید و endpoint آزمایشی پاس شدند. نتایج توسعه، بسته و نصب از هم مشخص‌اند.


نسخهٔ نهایی ۰٫۲٫۲ نصب شد (exit 0). هر ۱۵ بررسی روی خود نسخهٔ نصب‌شده پاس شد؛ app.asar نصب‌شده و بسته hash یکسان دارند. کلید آزمایشی پس از تست از مخزن امن حذف شد و کلیدهای واقعی کاربر دست‌نخورده‌اند.
