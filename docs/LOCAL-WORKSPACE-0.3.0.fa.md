# Bridge 0.3.0 — ساخت و نمایش داخل اپ

## استفاده

۱. برنامه را باز کن و مدل خودت را در تنظیمات وصل کن. انتخاب پوشه اجباری نیست؛ Bridge خودش فضای ساخت را ایجاد می‌کند.
۲. درخواست بده؛ مثلاً «یک صفحهٔ ورود بساز». برنامه را تأیید کن. ایجنت فایل را در فضای همان گفتگو می‌نویسد و همان‌جا آن را اصلاح می‌کند؛ کپی‌کردن کد به برنامهٔ دیگری لازم نیست.
۳. «اجرا و نمایش» را بزن. HTML داخل اپ باز می‌شود. برای پروژهٔ وب یا Python، فرمان مناسب تشخیص داده می‌شود؛ ابزارهای اجرا همراه اپ هستند. تنظیمات فرمان و پورت فقط در بخش پیشرفته‌اند.
۴. می‌توانی خروجی را در پنجرهٔ جدا یا مرورگر ببینی و اجرای آن را متوقف کنی. فایل‌های گفتگو و تاریخچه حفظ می‌شوند. Apply فقط برای تحویل تغییرها به پوشهٔ پروژهٔ انتخابی است؛ برای دیدن خروجی لازم نیست.

Docker، WSL و نصب جداگانهٔ Python/Node برای این مسیر لازم نیستند. Docker موجود روی دستگاه حذف نمی‌شود؛ این اپ به آن وابسته نیست. کد برنامهٔ وب باید از PORT و HOST محیط استفاده کند تا پورت آزاد خودکار انتخاب شود. HTML تک‌فایلی نیاز به نصب پکیج ندارد؛ پروژهٔ دارای وابستگی برای دریافت پکیج‌ها به اینترنت نیاز دارد.

## اجرای محلی و کنترل انسانی

فایل‌ها به‌صورت پیش‌فرض در پوشهٔ اختصاصی هر گفتگو داخل داده‌های Bridge قرار می‌گیرند. اجرای خروجی روی کپی همان فایل‌هاست تا فایل‌های اصلی یا کار ایجنت دست‌نخورده بمانند. Python و Node/npm داخل نصب‌کننده هستند.

این اجرا **sandbox سیستم‌عامل نیست**؛ فرمان‌ها دسترسی حساب ویندوز و شبکهٔ کاربر را دارند. محیط فرمان، کلید API مدل و توکن موتور را به ارث نمی‌برد؛ این موضوع تضمین جلوگیری از دسترسی کد مخرب به همهٔ فایل‌های سیستم نیست. عملیات حساس و اعمال فایل‌ها همچنان تأیید انسانی دارند. Stop از Windows Job Object برای بستن درخت پردازش استفاده می‌کند؛ خروج اجباری موتور نیز پردازش‌های همان job را می‌بندد.

گفتگوهای قدیمی فایل‌های خود را حفظ می‌کنند. در اولین انتقال یک گفتگوی Docker به اجرای محلی، تأیید برنامه و مجوزهای قبلی باطل می‌شود تا اختیار قبلی بی‌صدا به اجرای محلی تعمیم داده نشود. بررسی‌های ثبت‌شده با محیط قبلی، تأیید محیط جدید محسوب نمی‌شوند؛ در صورت نیاز یک گفتگوی تازه شروع کن.

## شواهد

- ۴۴۱ تست بک‌اند موفق و ۳ skipped در مجموعهٔ کامل؛ ۱۷ تست هدفمند برنامه/تایپوگرافی/اجرای محلی نیز موفق.
- مدل واقعی: ۱۳ بررسی موفق در مسیر برنامه‌ریزی، تأیید، تست شکست‌خورده، اصلاح منبع، موفقیت همان تست و حفظ پروژهٔ اصلی؛ اجرای کد با LocalRuntime انجام شد.
- پیش‌نمایش HTML/CSS/JS، پنجرهٔ جدا، Python و وب‌سرور Node، لینک واقعی و توقف در دسکتاپ بررسی شدند.
- شمار نهایی تست نسخهٔ بسته‌بندی‌شده در release.json تحویل ثبت می‌شود. مدل demo در تست رابط جای مدل واقعی معرفی نمی‌شود.

تمام زبان‌ها و فریم‌ورک‌ها آزمایش نشده‌اند. نصب‌کننده امضای ناشر ندارد؛ تاریخچه و کلیدهای شخصی داخل بستهٔ نصب نیستند. نشست پیش‌نمایش پس از restart خودکار شروع نمی‌شود.
