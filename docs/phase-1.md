## تحویل

کد در `E:/Codex File/Course/01/bridge-coding-harness` و اجرا از `Launch-Bridge.cmd`.
فایل اجرایی توسعه، Electron همین پوشه است؛ بک‌اند از Python همین پوشه بالا می‌آید.
نصب‌کنندهٔ مستقل متعلق به مرحلهٔ دوم است؛ نصب‌کنندهٔ Onboard محصول جدید محسوب نمی‌شود.

- appId: `ir.bridge.codingharness`؛ نام پنجره و package: Bridge Coding Harness.
- تنظیمات و product.db: `%APPDATA%/BridgeCodingHarness`.
- پروفایل Electron: `%APPDATA%/BridgeCodingHarness/desktop`.
- Credential Manager service: `bridge-coding-harness`.
- سرور توسعه: 3211؛ API دسکتاپ پورت آزاد و token تازه دارد.
- سورس، node_modules و venv در پوشهٔ جدید کپی مستقل هستند؛ import نصب editable نیز به همین پوشه متصل است.
- تنظیمات، مدل، کلید یا workspace برنامهٔ قبلی به‌صورت خودکار وارد نشده‌اند.
- Docker engine و تصویر sandbox وابستگی سیستمی مشترک‌اند؛ هر تسک نسخهٔ کاری و container جدا دارد.

سه تست اختصاصی استقلال home/vault/appId به تست‌های منتقل‌شده اضافه شدند.
مجوز AGPL-3.0 و انتساب upstream حفظ شده‌اند؛ README و third-party-sources را ببینید.

scripted است. آزمون provider واقعی و نصب و اجرای بستهٔ نهایی Bridge هنوز متعلق به مرحلهٔ دوم‌اند.
تست‌های UI تأیید و کیفیت از runtime ساختگی صریح استفاده می‌کنند؛ جایگزین اثبات Docker نیستند.
هیچ کلید کاربر در این گزارش‌ها ثبت نشده و هیچ تستی روی فایل واقعی کاربر اجرا نشده است.

## مرحلهٔ دوم

۱. تنظیم مدل واقعی در همین اپ مستقل، probe و اجرای یک سناریوی کامل با محدودیت هزینه.
۲. رفع هر نقص مشاهده‌شده، ساخت backend frozen و نصب‌کننده با هویت Bridge، نصب و smoke نسخهٔ نصب‌شده.
۳. تحویل نصب‌کننده، سورس و جدول شواهد پنج ویژگی و چهار معیار چالش.

دو مرحله حفظ می‌شوند؛ کارهای بالا مرحلهٔ سوم جدیدی ایجاد نمی‌کنند.
