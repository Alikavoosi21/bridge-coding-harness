# تطبیق با چالش — Bridge Coding Harness 0.2.10

حوزهٔ انتخابی کدنویسی است. طراحی/ویدئو و سلامت، گزینه‌های جایگزین چالش‌اند و به دامنهٔ این محصول اضافه نشده‌اند. محصول اپ مستقل ویندوزی با Electron، رابط فارسی و طراحی سبز Bridge، و موتور محلی Python/FastAPI، Deep Agents و LangGraph است.

## پنج قابلیت الزامی

## خروجی‌های مورد انتظار

- **حلقهٔ کامل:** TaskController برنامه و اجرای تأییدشده را روی یک thread پایدار هدایت می‌کند؛ VerifyHook نتیجهٔ واقعی checkها را ارزیابی و مدل را برای اصلاح بازمی‌گرداند. LangGraph checkpoint و SQLite تاریخچه و تصمیم‌ها را نگه می‌دارند.
- **اتصال مدل و ابزار:** API key و دریافت مدل‌های سرویس در خود اپ؛ ابزارهای فایل و shell واقعی. کلید به کانتینر یا پیش‌نمایش تحویل داده نمی‌شود. نبود Docker به shell میزبان تبدیل نمی‌شود.
- **قابلیت ماژولار:** Skill دستور، فایل مرجع و اسکریپت همراه دارد. فعال‌سازی Skill اجرای خودکار یا افزایش اختیار ایجاد نمی‌کند؛ اسکریپت از ابزار اجرا و همان HITL استفاده می‌کند.
- **کنترل مستقیم:** ویرایش برنامه، اقدام و فایل؛ انتخاب فایل‌های اعمال‌شونده، توقف و ادامه/بازیابی. چت مرکز جریان کار است.
- **اپ نصب‌شدنی:** نصب‌کنندهٔ Windows x64، میان‌بر مستقل، موتور همراه و حذف‌کننده؛ Node/Python میزبان برای اجرای خود اپ لازم نیست. Docker و حساب/API مدل، وابستگی بیرونی اجرای واقعی‌اند.
- **دیدن محصول ساخته‌شده:** HTML تعاملی درون اپ، پنجرهٔ جدا، لینک مرورگر؛ اجرای Python/Node و سرور وب روی کپی جدا، لینک محلی پس از پاسخ واقعی و توقف قابل بررسی.

## اصلاح این بررسی

در آزمون واقعی ابتدا مدل به اجرای check نرسید: پیام پیش‌نیاز baseline را با انتظار برای approval اشتباه گرفت. اکنون context اجرای تسک، فرمان‌های الزامی و cwd دقیق `/workspace` را اعلام می‌کند؛ پیام gate صریحاً تفاوت پیش‌نیاز با رد/انتظار مجوز را توضیح می‌دهد. محدودیت امنیتی تطبیق دقیق فرمان برداشته نشد. دستور متناقض «فقط یک به‌روزرسانی todo در هر turn» نیز با به‌روزرسانی هنگام تغییر پیشرفت جایگزین شد.

آزمون دوباره با مدل واقعی `deepseek-v4.1-flash` و Docker: **۱۳/۱۳ موفق**؛ برنامهٔ پایدار، تأیید نسخه، اجرای تست شکست‌خورده، اصلاح منبع توسط مدل، موفقیت همان تست، حفظ فایل تست و پروژهٔ اصلی و آزادشدن worker تأیید شدند. Skill همراه `coding-checks` واقعاً توسط ابزار read_file خوانده شد. کلید، endpoint خصوصی یا فایل کاربر در گزارش تحویل قرار نمی‌گیرد.

## محدودیت‌های صریح

برنامه تضمین حل تمام خطاهای هر پروژه را نمی‌دهد؛ اگر دو اصلاح کافی نبود، کاربر تمدید یا توقف را انتخاب می‌کند. «بدون ارور» فقط نسبت به checkهای واقعاً اجراشده معنا دارد؛ بدون check پیکربندی‌شده، تأیید کیفیت خودکار ادعا نمی‌شود. تمام زبان‌ها و فریم‌ورک‌ها آزمایش نشده‌اند؛ شواهد اجرایی شامل Python، JavaScript، TypeScript، npm/pip و HTML است. نشست پیش‌نمایش پس از restart خودکار از سر گرفته نمی‌شود. نصب‌کننده امضای ناشر ندارد.

جدول معیارها پوشش قابلیت‌ها را نشان می‌دهد و وعدهٔ نمرهٔ ۲۰۰ نیست. شواهد نهایی نسخهٔ بسته‌بندی‌شده و شمار تست‌ها در `release.json` کنار فایل نصب قرار می‌گیرند.
