# اجرای محلی و ارائهٔ کلاسی

این نسخه روی همین میزبان با Node 24 و Python 3.11 داخل `backend/.venv` بررسی می‌شود. Docker نصب نیست: راه‌اندازی، گفتگو، برنامه‌ریزی، تاریخچه و عیب‌یابی قابل‌استفاده‌اند؛ اجرای shell و تغییر توسط ایجنت بدون محیط ایزوله فعال نمی‌شوند. اتصال به مدل واقعی اختیاری است؛ مدل «نمایشی» باید در ارائه صریحاً معرفی شود.

## اجرای برنامه

PowerShell را در پوشهٔ `onboard-harness` باز کنید. اگر وابستگی‌ها موجودند، نصب را تکرار نکنید. برای آماده‌سازی اولیهٔ checkout جدید:

```powershell
npm ci
uv sync --project backend --frozen --extra dev --python 3.11
```

در ترمینال اول، از پوشهٔ `onboard-harness/backend`:

```powershell
.\.venv\Scripts\python.exe -m server --dev
```

در ترمینال دوم، از پوشهٔ `onboard-harness`:

```powershell
npm run build
npm run start
```

برنامه در `http://localhost:3210` و موتور در `http://127.0.0.1:8765` بالا می‌آیند. `--dev` فقط احراز هویت token موتور را برای اجرای مرورگری محلی غیرفعال می‌کند؛ محدودیت localhost و Origin برقرار است. برای کدنویسی رابط می‌توان به‌جای build/start از `npm run dev` استفاده کرد. بازکردن مرورگر، reload یا خواندن تاریخچه اجرای تازه‌ای ایجاد نمی‌کند.

اجرای پوستهٔ دسکتاپ با همان محیط Python موجود:

```powershell
npm run desktop:preview
```

این دستور static export می‌سازد و Electron را اجرا می‌کند؛ Electron موتور محلی را با token اختصاصی بالا می‌آورد. بستن پنجره در زمان کار، تصمیم ماندن/توقف‌وخروج می‌خواهد. توقف تأییدنشده با نتیجهٔ موفق اشتباه نمی‌شود. تست خودکار مرورگر، اثبات اجرای دیالوگ native نیست.

## داده و پشتیبان

دادهٔ محصول پیش‌فرض در `%APPDATA%\OnboardHarness` است و از پوشهٔ پروژه جداست. مسیر دقیق در تنظیمات ← داده‌ها و عیب‌یابی دیده می‌شود. `HARNESS_HOME` مسیر داده را برای اجرای آزمایشی تغییر می‌دهد. برای پشتیبان، ابتدا کارها را متوقف و اپ/موتور را ببندید، سپس کل پوشهٔ داده را کپی کنید؛ فقط کپی product.db در زمان اجرای موتور پشتیبان کامل نیست. checkpointها، pins و journalها نیز باید حفظ شوند. کلیدها در keychain سیستم‌اند و وارد ZIP عیب‌یابی نمی‌شوند.

اگر درایو C فضای کافی ندارد، پیش از اجرای موتور می‌توانید `HARNESS_HOME` را در همان PowerShell روی پوشه‌ای در درایو دارای فضای آزاد بگذارید. این پوشه باید خارج از پروژه‌ای باشد که به ایجنت می‌سپارید. تغییر مسیر، داده‌های قبلی را منتقل یا حذف نمی‌کند؛ برای ارائه از workspace مشخص و کوچک استفاده کنید. در بررسی این مرحله C حدود ۶۰MB آزاد داشت، بنابراین fixtureهای تست در `.test-runs/` روی E اجرا شدند؛ فایل‌های شخصی C پاک نشدند.

پیش از پاک‌سازی، پیش‌نمایش را بخوانید و cacheهای موردنظر را انتخاب کنید. پیش‌فرض ۳۰ روز و حد پیشنهادی ۵GB است؛ تغییر سیاست خودش چیزی حذف نمی‌کند. فقط cache قابل‌بازسازیِ task تمام‌شده پاک می‌شود. تاریخچه، کد کاری، baseline، pins، checkpoint و journal باقی می‌مانند. cache مرتبط با recovery، لینک و فایل ویژه حذف نمی‌شود. کمبود فضای دیسک task تازه را متوقف می‌کند؛ برنامه پروژه یا تاریخچه را خودکار پاک نمی‌کند.

برای عیب‌یابی، پیش‌نمایش JSON را ببینید، ZIP محلی بسازید و در صورت نیاز دریافت کنید. بسته شامل نسخه‌ها، وضعیت کلی runtime و تعدادهای تجمیعی است؛ raw log، کد، prompt، diff، URL مدل، نام کاربر و مسیر خصوصی ندارد. هیچ upload یا ارسال خودکاری وجود ندارد.

## خطاهای معمول

- موتور در دسترس نیست: ترمینال Python و `/health` را بررسی کنید؛ این مشکل با نصب Docker یکی نیست.
- Docker نصب نیست یا image آماده نیست: حالت فقط‌خواندن طبیعی است. روی این میزبان نصب Docker/WSL خودکار انجام نمی‌شود و host-shell جایگزین وجود ندارد.
- مدل واقعی کلید یا توان ابزار ندارد: تنظیمات مدل و probe را بررسی کنید؛ اتصال مدل، مجوز شبکهٔ کانتینر نیست.
- پورت اشغال است: اجرای قبلی خودتان را ببندید؛ فرایند نامرتبط را حذف نکنید.
- task نیازمند بازیابی است: فایل‌های فعلی و journal را بازبینی کنید. unknown را با اجرای مجدد فرمان حل نکنید.

## بسته‌بندی اختیاری موجود

`npm run desktop:build` همان مسیر PyInstaller + electron-builder موجود را استفاده می‌کند؛ frozen engine باید Skill همراه، Dockerfile و SQLite checkpointer را حمل کند. تغییر source یا uv.lock باعث بازسازی engine قدیمی می‌شود. فایل‌های برند، GIF، poster و فونت از static export می‌آیند. این دستور نصب وابستگی build و دانلود Electron ممکن است لازم داشته باشد؛ ساخت installer و انتشار gate پروژهٔ کلاسی نیستند. `release-download/` ورودی کاربر است و دست‌کاری نمی‌شود. signing، auto-update و تست ویندوز تمیز در دامنهٔ فعلی نیستند.

ارائهٔ پیشنهادی: راه‌اندازی و برچسب demo → برنامه و تأیید انسانی → تاریخچه و بازبینی تغییرها → بازیابی بدون replay → پیش‌نمایش عیب‌یابی و پاک‌سازی. نمونه‌های runtime ساختگی را صریحاً از اجرای واقعی Docker جدا کنید.
